# financial_metrics 정밀화 — hedge 역추적과 전수 audit

## Context

웹(claude.ai)에서 "SK하이닉스 26년 1분기 실적" 질의가 비정상적으로 오래 걸리고,
이어진 "현금흐름·재무건전성 분석"에는 "확인 필요"가 3건 붙었다. 사용자: "불확실하다는
말이 많으면 믿고 쓰기 곤란하지 않을까?" — hedge의 원천을 추적하니 전부 tool의 실제
파싱 결함이었고, 교정 후 시장 412사 전수 audit으로 수렴을 확인했다.

## 핵심 원리 — tool 출력이 틀리면 모델이 그 비용을 대신 낸다

- Q4 행에 연간 누적치(97.1조)가 분기값처럼 섞이자, 호스트 모델은 ① 값을 의심하고
  ② 9개월 누적을 역산해 standalone을 수동 계산하고 ③ 가짜 `revenue_decline_qoq`
  alert를 반박하는 추론을 돌렸다. **사용자가 본 "느린 tool"의 정체는 모델의 보정 노동.**
- 역으로, 모델의 hedge("계정 매칭 오류 의심", "미파싱")는 **공짜 버그 리포트**다.
  3건 추적 → 3건 모두 실제 결함 (이자보상 금융비용 오염 / 차입금 패턴 미스 / 분기 CF 결측).

## Did (교정 9건)

1. **Q4 누적차분** — Q1~Q3 `thstrm`=3개월·`thstrm_add`=누적, 연간(11011)=누적 실측 →
   Q4 = 연간 − Q3누적 ([[dividend-source-of-truth-260609]] 패턴 재사용). QoQ·YoY 전 행 기본 동봉.
2. **fs_div 필터** — fnlttSinglAcnt는 파라미터 무관 CFS+OFS 동시 반환(KB금융 실측).
   first-match가 행 순서에 의존하던 잠재 버그 제거.
3. **이자보상배율** — '금융비용' fallback이 환손·평가손 총액 오염: SK하이닉스 3.77→50.3배,
   삼성전자 3.72→**92.8배** (둘 다 내내 왜곡이었음). IS 이자비용 → CF 이자의 지급 체인.
4. **이자지급 변형 정확일치 세트** — substring "이자지급"은 "신종자본증권이자지급"(0원)에
   선매칭(POSCO 실측). 변형은 probe로 수집해 **정확 일치만** 추가 → 커버리지 59%→97%.
5. **차입금 generic** — 계정명이 그냥 "차입금"(SK하이닉스)·"차입부채"(금융사) 합산.
   단기/장기금융부채 류는 파생·기타 포함이라 **의도적 미채택** (과대계상 > 커버리지).
6. **분기 fallback 연도 CF 결측** — acnt_all이 11011 고정, used_rc 미전파 → 전파.
7. **재작성 gap flag** — 분기합≠연간(분할·중단영업·감사조정)은 원천 속성. 기계용
   flag(>0.01%)와 사람용 warning(>0.5%) 이원화 + 손익 3키 전부 검사(루닛: 매출 일치,
   영업이익만 불일치 — 중단영업 류는 하단만 영향).
8. **EBITDA 표시 정책** — D&A 추출 가능 24%뿐(다수 회사가 CF에 '조정' 합계만 공시,
   probe 30사에 상각 행 부재). 미산출 시 OP+0=OP로 내보내던 무의미 값 제거,
   **결측이면 줄 자체 생략** (산출 불가 안내도 hedge로 읽힘).
9. **잠식률 표시** — 정상 기업의 거대 음수(-48,514%)는 상태만 표기.

## 검증 방법론 (수렴 확인)

- **불변식 기반**: 4분기 합=연간(손익 3키) / FCF=CFO−CapEx / 듀퐁곱=ROE / 부채비율 /
  순현금 / 마진 — "바뀐 것"이 아니라 전체 정합을 검사 (selfcheck 원칙).
- **라운드 점증**: 4사 → 10사 → 엣지 14 → 코스닥 16 → 20 → **시장 412사 × FY24·25**
  (KOSPI 시총 300 + KOSDAQ 100 + 엣지, 회사당 10콜 ~4,200콜, 한도 절반 이하).
  발견 강도가 구조 버그 → 처리 누락 → 임계값 → 표시 정책 순으로 약해지며 수렴.
- **미추출은 probe로 원인 확정 후 처방 분기**: 패턴 변형(고침) / 원천 한계(표시 정책) /
  과대계상 위험(의도적 미채택 + 기록).

## Takeaway

- **모델의 hedge는 tool 결함의 증상이다.** "불확실 멘트가 많다"는 불만은 프롬프트가
  아니라 데이터 파이프라인에서 고친다. 맞는 숫자 + 결측엔 단정적 사유("금융사라 매출
  계정 없음") — 모델은 이유가 단정되면 의심 추론을 멈춘다.
- **누적 공시 체계에서 "기간 값"은 항상 차분으로 만들어라** — dividend에 이어 두 번째
  같은 교훈. DART 정기보고서의 모든 손익은 누적이 기본이다.
- **substring 패턴의 수명은 짧다** — 변형 커버리지가 필요해지면 정확 일치 세트로
  전환하라. probe(미추출 표본의 실제 계정명 빈도)가 세트를 만들어준다.
- **커버리지를 올리지 말아야 할 때가 있다** — 단기/장기금융부채를 차입금으로 잡으면
  숫자는 채워지지만 틀려진다. 결측이 오류보다 낫다.
- **결측 표시도 설계다** — "산출 불가" 안내조차 hedge로 읽힌다. 신뢰를 만드는 건
  '없음의 설명'이 아니라 '없음의 침묵 + 있는 값의 정확성'일 때가 있다.
