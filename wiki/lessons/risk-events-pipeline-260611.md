# risk_events 구축 파이프라인

## Context

"중대재해 공시 4종으로 tool 넣을까?"에서 출발해 하루 안에:
중대재해 단독 tool(serious_accident) 신설 → 같은 프로파일 공시 5종 실측 발굴 →
risk_events 6카테고리 통합 → 본문 359건 전수 audit → **활성 3종 + mute 3종** 스콥 확정.
각 단계가 다음 단계의 근거를 실측으로 만들어낸 파이프라인 기록.

## 파이프라인 (재사용 가능한 방법론)

1. **검증 먼저, 구현 나중** — 키워드·코드 가설을 세우면 즉시 시장 실측:
   - per-company 표본(고위험 49 → 220 → 305사)에서 `넓은 type vs detail code 차집합 0` + 전체유형 풀스캔 누수 0 ([[page-cut-detail-code-260609]] 방법론).
   - **시장 전체 90일 sweep**(I001 162p + B001 21p + I003 21p, ~190콜)이 한 번에 셋을 줌:
     후보 공시 발굴(빈도 실측) / 제목 변형 카탈로그 / 채널 매핑. 후보 선정을 감이 아니라 건수로.
2. **같은 프로파일이면 한 tool** — 희소(월 수~수십 건)·정형(라벨 필드)·키워드 타겟 가능 공시는
   카테고리로 묶는다. 검색 sweep·파서 헬퍼·supersede·시장 스캔 인프라가 전부 공유됨.
   시장 스캔 1회(~45콜)로 전 카테고리 동시 수확 — tool을 쪼개면 같은 sweep을 중복 지불.
3. **본문 파서는 라벨 추측 금지 — 전수 audit으로 수렴** — 90일 윈도우 186건 전수 파싱:
   파생손실 4%(추측 라벨) → 실물 라벨(`손실누계잔액(원)(기신고분 제외)`) 교정 → 92%.
   **직전 90일 173건 out-of-sample 재검증**에서 변형 추가(`손실발생금액` SK하이닉스형) → 100%.
   두 독립 윈도우에서 교정분이 수렴(2건→0건)하면 안정 판정.
4. **신설 직후가 통합·rename 적기** — serious_accident는 ship 몇 시간 만에 risk_events로
   흡수. 의존 사용자 0인 시점의 재구성은 비용 0, 미루면 커넥터 마이그레이션 비용 발생.
   (cf. [[tool-naming-discovery-260610]] — corporate_deals rename도 같은 원리)
5. **스콥 축소는 삭제가 아니라 mute** — 검증 끝난 파서 3종(파생손실·회생부도·해산)을
   버리지 않고: 기본 조회 키워드·분류·desc에서 제외(=라우팅 차단), 명시 category 요청 시
   warning과 함께 동작, 재활성화는 `_ACTIVE_CATEGORIES` 한 줄. **desc 비노출 = 사실상 비활성**
   — 라우팅 LLM은 desc만 보므로 (naming lesson의 역방향 응용).

## Domain 발견 (DART 리스크 공시의 구조)

- **채널이 단계별로 갈린다**: 회생절차 개시'신청'(회사 제출)=B001 주요사항보고서,
  개시'결정'(법원발)=I001 거래소공시. 부도·영업정지·해산도 B001 채널 존재.
  중대재해·횡령·파생·생산중단은 I001 전용(B001 90일 0건). → 리스크 공시는 I001+B001 동시 조회.
- **공시 주체는 대형 원청·지주사에 편중**: KOSDAQ 상위 100 보유 0, 중소형 건설 35사 0건.
  지주사가 자회사 사고를 (종속/자회사의 주요경영사항)으로 받아 공시 → 무공시 ≠ 무사건.
- **지주사+사업회사 이중 공시**: 같은 사고를 한화(종속)와 한화에어로(본인)가 각각 공시.
  사상자 집계는 (발생일자+장소 정규화) supersede 키 — `㈜` vs `(주)` 표기 차이로
  사망 5명이 이중 집계되던 실측 버그. **정규화 없는 자연키는 키가 아니다.**
- **generic 제목도 키워드가 뚫는다**: `투자판단관련주요경영사항 (1차 부도 발생)`,
  `기타주요경영사항 ('회생절차…' 재항고 취하)` — DART report_nm에 괄호 사유가 포함되므로
  제목 키워드 매칭이 generic 제목까지 커버 (두 윈도우에서 각 1건씩 일관 확인).
- **제도 시점 함정**: 거래소 중대재해 수시공시는 2025-10 신설(실측 최초 2025-10-29).
  이전 구간 무공시를 무사고로 읽으면 오독 — 제도 신설 공시는 시작 시점을 실측해 warning으로 박아라.

## Takeaway

- 후보 발굴→채널 매핑→빈도까지 **시장 sweep 한 번(~190콜)으로 끝내라**. 표본 회사를 늘리는 것보다 싸고 완전하다.
- 파서 라벨은 작성 시점엔 항상 추측이다 — **연속 두 윈도우 전수 audit으로 수렴 확인** 후에야 신뢰.
- 스콥 결정은 코드 삭제가 아니라 **활성 집합 선언**으로. 검증 비용(359건)은 자산이다.
- 필드 추출률은 가짜 매칭을 빼고 세라 — 부도 양식의 "법원" 오추출(98%)이 가드 후 87%로
  떨어진 건 회귀가 아니라 **정직해진 것** (해당 필드가 실제 없는 공시).
