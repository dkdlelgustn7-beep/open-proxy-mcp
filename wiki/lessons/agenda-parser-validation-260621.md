# 안건 파서 검증 — 측정 함정 5패턴과 프로토콜 (260621)

2026-06-21 주총 안건/정기·임시 파서를 6사이클(detect 재작성 → marker/zone → bleeding →
하위안건 분리 → proposer 복원 → 빈제목 추론) 개선하며 production까지 배포했다. 그 과정에서
**측정 스크립트가 반복적으로 거짓 결론을 냈고, 직접 검증으로만 잡혔다.** 다음에 같은 함정을
피하기 위한 기록. 검증셋은 통합 픽스처(2026 3/1~5/15 코스피·코스닥 3,016건, 정기 2,849).

## 측정 함정 5패턴

| 패턴 | 사례 | 단정 → 실제 | 대응 |
|---|---|---|---|
| **A 로그/라벨을 관측으로 착각** | `IMAGE_NOTICE` | "본문이 이미지" → 실제 text 5만 자 (로그가 "추정"이라 했는데 결론으로 씀) | 즉시 확인 가능한 관측(text 길이·offset)부터 찍는다 |
| **B 측정 정답(ground truth)도 불완전** | "미상 105건" · v2가 파멥신·메디콕스 오판 | "detect 사각지대" → 측정함수 `head 2500` 한계(정정공시 앞블록) / "회귀" → 정답 v2가 틀림 | 의외 결과면 **측정 정답 함수부터 의심**. 정답도 표본으로 검증 |
| **C 검증 경로 ≠ production** | "안건 0개 33건" | "버그" → text 경로만이었고 production은 html 경로라 정상 | 검증은 반드시 **production 경로(`parse_agenda_xml(text, html=html)`)로 재현** |
| **D 정규식 과대/과소 매칭** | "bleed 100건" · "proposer 손실 56건" | 날짜 `2025.1.1`의 `1.` 오탐 / `주주제안권`·`인입보고`·사유문구 false positive | 스크립트 빈도는 **상한/하한**일 뿐. 직접 표본으로 정밀도 추정 |
| **E 변경분만 보고 전체 영향 안 봄** | "하위분리 8건 통과" | 8건만 직접 봐서 통과 판정 → 전수 diff 하니 국영지앤엠 빈제목 부작용 | **변경분 + 전수 diff** 둘 다. 변경 안 된 것도 깨질 수 있음 |

## 왜 반복됐나 (근본 원인)

1. **빠른 결론 > 정확한 결론** — 스크립트 숫자를 사실로 받고 곧장 서사로 직행(확인 1줄이면 막혔을 것).
2. **내 스크립트 과신** — "측정은 맞고 대상이 문제"라 가정. 측정 도구의 숨은 가정을 검증 안 함.
3. **검증을 "시키면 하는 일"로 취급** — 기본 동작이 아니라 외부 지적에 대한 반응이었음.
4. **메모리 교훈 있어도 능동 적용 안 함** — 기록만 하고 매 측정마다 떠올리지 않음(수동).

→ 한 줄: **검증이 default가 아니라 사용자 안전장치에 의존했다.**

## 검증 프로토콜 (확립)

파서 개선·검증 시 항상:
1. **html 픽스처 0콜** — production 경로(`parse_agenda_xml(text, html=html)`)로, DART 재호출 없이 전수 재파싱.
2. **전수 diff** — before/after 전체 비교. regression = 기존 정상분(번호·계층·제목)이 하나도 안 깨짐.
3. **직접 표본** — 스크립트 결과를 단정하기 전, 균등 샘플(120 → 300 → 공시 단위)을 **눈으로 읽는다**.

## 보고 전 체크리스트 (측정 결과마다 자문)

- [ ] 이 측정의 **숨은 가정**은? (head 제한·경로·패턴 엄격도)
- [ ] **정답(ground truth)**도 검증했나?
- [ ] **production 경로(html)**인가?
- [ ] 변경분뿐 아니라 **전수 영향**을 봤나?
- [ ] **의외 수치**면 — 결론 전에 직접 표본을 읽었나?
