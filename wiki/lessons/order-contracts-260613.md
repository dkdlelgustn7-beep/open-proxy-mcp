# 수주 tool 신설 (order_contracts)

## Context

적자 디폴트인 코스닥 바이오/기술주는 재무지표(ROE 등)만으론 안 보이는 축이 있다 —
**수주 = 미래 매출 가시성**. 단일판매·공급계약 공시(일반/자율공시/자회사)가 그 시그널인데,
corporate_deals가 같은 공시를 '일감몰아주기' 관점으로만 다뤄 수주 긍정 시그널이 약했다.

## 현황 진단 (구현 전)

- 검출은 됐다 — corporate_deals가 I001에서 일반+자율공시를 다 잡음(자율공시도 I001, 시장 실측).
- 그러나 (1) 기본 모드는 메타만(`include_details=False`) (2) **본문 파싱이 공백 변형에 깨짐** —
  `매출액 대비(%)`의 공백 한 칸 때문에 매출대비%가 전부 None, 코스닥은 금액조차 None.
  적자기업에 가장 중요한 '매출 대비 큰 수주'가 비어 있었다.

## Did

별도 tool `order_contracts` 신설 (16→17). corporate_deals와 같은 공시, 반대 관점(수주=긍정).

- **파싱 견고화** — 계약명 라벨 3종(`체결계약명`/`세부내용`(자율공시)/`판매ㆍ공급계약 내용`),
  금액 단위((원)/(천원)/(백만원)) 환산, `매출액\s*대비` 공백허용. 코스닥·조선·로봇·바이오 전수 통과.
- **기재정정 dedup + diff** (핵심) — 수주는 변경계약이 흔하다. 정정본 본문에 정정전/정정후가
  같이 있어 증액/감액을 직접 추출. dedup은 **multi-signal**: (계약명+상대방) 그룹 + 정정본의
  *정정전 금액* = 이전 건 금액이면 같은 계약 체인(최신본 유효). 금액 체인 불일치면 별개.
- **수주 시그널 요약** — 외부(계열 제외) 건수·총액·매출대비 최대/합계·정정 건수.
- **proxy_advise 매트릭스 fact** — 사내이사 성과(ROE/부채/CSR) 옆에 수주를 **별도 fact**로
  (점수 미반영 — compute_performance가 order를 안 받아 구조적 보장). 적자 코스닥에서
  수주 부재를 성과 저조로 오판하지 않게.

## 전수조사가 잡은 것 (multi-signal 검증)

사용자 지시로 전수조사하며 구현 — 두 버그를 실측이 잡음:
- 🔴 **한화 MCS Plant 정정 diff**: 표가 `계약금액(원) 매출대비(%) | 전값 | 후값` 구조라 정규식이
  라벨 뒤 숫자(294조·4)를 전/후로 오인 → 실제 **2940억→4245억(+44.4%)**. 큰금액 2개·소수 2개를
  순서로 뽑게 수정 (표양식 2종: 레인보우 '라벨 뒤 값' vs 한화 '라벨 앞 몰림').
- 🔴 **HD현대 자율공시 계약명 '?'**: 자율공시는 `체결계약명`이 아니라 `세부내용`(VLGC 2척) 라벨.
- 코스닥 검증: 에스티팜(올리고 898억·매출대비32.8%), 바이넥스(CDMO), 파마리서치(REJURAN® 31.3%).

## 시장 전수 audit (450사) — 단위 불변식이 정정본 버그 2개를 연쇄로 잡음

baseline 450사 전수 (총 482 DART콜·9분·분당 48 — 콜 누적을 배치마다 출력하는 재사용
audit 패턴). 수주 보유 167사, 유효계약 1060, **정정 603**(계약의 57% — 수주=변경계약 흔함 실증).

핵심 검증 = **단위 정합 불변식: 계약금액 ÷ 최근매출 × 100 ≈ 매출액대비%**. 이게 정정본
파싱 버그를 2라운드에 걸쳐 잡았다:

- **1차 (unit_mismatch 48)**: `_correction_diff`가 정정블록의 계약금액·최근매출을 [정정전/후]로
  오인 → `amount_after`가 최근매출값이 되어 contract_amount를 오염 (포스코 EV양극재 실제
  1.8조인데 4.7조). → 정정블록 `계약금액(원) [전] [후]` **라벨 직접 매칭** (포스코 '라벨 뒤 값'
  양식 우선, 한화 '라벨 몰림'은 최근매출 라벨 이전 구간 fallback).
- **2차 (unit_mismatch 74)**: 1차 수정 후 새 패턴 — `금액=정정후` / `매출대비=정정전`이 섞임
  (한화 MCS 5.7% vs 공시 294%). 근본 원인: **정정본은 `[정정전/후 테이블] + [정정후 반영
  재공시 본문]` 2부 구조**인데, 파서가 테이블의 정정전 값을 먼저 잡았다. → 정정본은 재공시
  본문(정정후)에서 금액·매출대비·계약명을 파싱하도록 수정. diff는 테이블에서 별도 추출.
- **최종: unit_mismatch 5 (0.5%)** — 남은 건 개별 양식 엣지(앱클론 매출대비 396% 같은 소형
  바이오 대형수주는 정상, 스피어 1건 단위 의심). flag 4사.

추가 발견: **계약금액이 달러 기준**인 공시(포스코 USD 10.7억×환율) — 본문에 원화 환산값이
같이 있어 그걸 사용. 통화도 '단위'의 한 축.

## 2차 audit 라운드 — 코스닥 바이오 + 파싱 누락 클러스터 (regression 0)

수정 후 450사 재audit를 반복하며 새 엣지를 추가로 잡음 (콜 482·8.9분 불변 = 성능 regression 0):

- **`_pct` 천단위 콤마** — 적자 CDMO는 매출대비%가 천%를 넘어 `3,140.24`처럼 콤마가 생기는데
  `[\d.]+`가 `3`에서 멈춰 3.0%로 오파싱(프레스티지바이오로직스). `[\d,]+` 허용 → unit_mismatch
  5→0. **적자기업에서만 터지는** 버그 — 정확히 이 tool의 타깃 영역.
- **이행금액 정정 오인** — `계약금액 X원에서 총 이행금액은 Y원`(공시유보 해제 안내)을 정정
  감액(-70.7%)으로 오인 → '이행금액' 패턴이면 correction_diff 비움.
- **영문 장문 계약명** — 대한전선 `TERM CONTRACT FOR THE SUPPLY, DELIVERY…`(140자)가 길이
  제한(50)에 걸려 누락 → 200자로. no_name 34→0 (전선사 클러스터 전체 복구).
- **정정 서술형 금액** — LG엔솔 `'계약금액(원)' - 4,082…`(따옴표·하이픈) → 노이즈 허용.
- **금액 미변경 정정 체인 상속** — 매출대비만 정정해 정정본 계약금액이 `-`인 경우 체인
  이전본 금액 상속.

남은 no_amount 29는 **파싱 실패가 아니라 정상** — LG엔솔 등 글로벌 계약의 달러 표기(`$2,795M`)
또는 공시유보(`계약금액(원) -`, 경영상 비밀). 본문에 원화 금액이 없는 케이스. audit의 단순
no_amount 카운트가 '비공개'와 '실패'를 구분 못 하는 한계 (지표 자체의 오탐).

도메인 패턴: 순수 신약/기술수출 바이오(알테오젠·HLB·휴젤)는 단일공급계약 미사용(no_filing 정상),
CDMO/원료/백신(프레스티지·SK바사·에스티팜·바이넥스)만 수주 시그널. **적자 CDMO 매출대비
수백~수천%가 미래매출 가시성 핵심.**

## 바이오 섹터 전수조사 (DART KSIC C21, 206사)

전체 시장 audit이 baseline 450(대형 제약 54개 위주)이라 정작 이 tool의 타깃인 코스닥 소형
바이오가 빠져 있었다. **DART 업종코드(induty_code 21xxx = C21 의약품)로 상장사 3970개를
전수 필터**해 바이오 universe 206개를 확보(`extract_bio_universe.py`), order_contracts 전수.

- **파싱 완벽** — no_name 0 / no_amount 0 / no_revenue_ratio 0 / unit_mismatch 0 (209콜·3.8분).
  전체 시장에서 남았던 no_amount(달러·공시유보)도 바이오엔 없음(원화 계약 위주).
- **수주 보유 51/206 (25%)** — 신약/기술수출(no_filing)을 빼면 CDMO·원료·진단·제약 계열.
- **적자 가시성 시그널 실증** — 프레스티지바이오로직스 3140%, 피씨엘(진단) 908%, 케어젠 82%,
  이엔셀(세포치료 CDMO) 79%, 에스티팜 65%. 매출의 수배~수십배 수주 = 재무지표로 안 보이는 축.
- **바이오 정정율 75%** (117/157) — 전체 시장 57%보다 높음. CDMO 위탁생산이 변경계약이
  잦아 dedup/diff가 특히 중요. flag 1건(프레스티지 3140%)은 진짜 — audit `>1000%` 기준이
  적자 바이오엔 과민한 false positive.

→ 섹터 전수조사는 **업종코드(KSIC) 필터로 universe를 정확히 좁히는 게 핵심.** 회사명 키워드는
누락(셀트리온·알테오젠 등 키워드 없음), 시장 baseline은 대형주 편향. induty_code가 정답.

## 해지(termination) 파서 전수조사 (바이오16 + baseline32 + 전업종19 = 67건)

체결만 잡던 시기엔 해지가 no_filing으로 위장됐다(종근당홀딩스 termination-only). `_parse_termination`
신설 후 **해지 파싱 자체를 전수 검증**해 라벨 변형군을 잡았다. audit `_check`에 해지 5축
(term_no_name/counterparty/amount/revenue_ratio/unit_mismatch) 추가.

- **바이오 206사 → 해지 16건**: 계약명 7·상대방 4 누락. 두 라벨 변형이 원인 —
  - 계약명: 해지 본문은 `판매ㆍ공급계약 **해지내용** [계약명]`(체결의 `내용`과 달리 `해지` infix).
    → 라벨 `(?:해지\s*)?내용` 허용. 휴마시스(체외진단키트)·케어젠·코오롱(인보사)·녹십자엠에스 복구.
  - 상대방: 영문사 슬래시(`EMS S/A`)·장문 구사명 병기(`GreenPine…(구 Tianjin…)` 70자)가
    val_chars(슬래시 없음)·길이 50에 걸림. → `/` 추가 + 50→80. 대웅·신풍제약·녹십자엠에스 복구.
- **baseline 450 → 해지 32건**: `세부물건`(건설 자율공시 계약명 라벨, 대우건설 '대장~홍대
  광역철도…') 1건 추가. 나머지 2건(포스코퓨처엠 상대방·현대건설 NEOM 금액)은 원문이 `-`인
  **정상 비공개** — audit가 비공개를 누락으로 오탐(no_amount 한계와 동형).
- **전 업종 균등샘플 662사 → 해지 19건**: 전 5축 **0 누락**, 새 라벨 없음 → 종결.

### 샘플 설계 교훈 — "전수 ≠ 적절"

처음엔 "모든 종류 기업"을 전 상장사 3970 × 24개월 **전수**로 과대해석 → 90분 콜·production
패턴(개별 조회)과 괴리. 중단하고 **전 상장사 균등간격 샘플**(`names[::6]` = 662사)로 재설계:
상장순서가 규모·업종·연도를 자연 혼재시켜 대표성은 유지, 크기는 1/6(13.5분, 분당 51/910).
→ 견고성 검증의 목표는 **라벨 변형군의 포화**지 전수가 아니다. 균등간격 샘플로 충분.

도메인 패턴: 해지는 대부분 **과거(2년+) 체결의 해지**라 체결이 24개월 window 밖 → 체결-해지
매핑(dedup 키 재활용)은 '같은 window 내 빠른 해지'(수주 후 1년 내 해지=강한 부정신호)만 잡힘.
오래된 수주 해지는 해지 단독 표시 + 순수주(외부 체결−해지)에 반영.

### corporate_deals 파서 공유 — 같은 공시는 같은 견고함

corporate_deals도 **같은 단일공급계약 공시**(I001)를 일감몰아주기 관점으로 파싱하는데,
`_parse_supply_contract_document`가 `체결계약명`/`계약상대`만 봐 해지 계약명을 4/4 통째로
놓쳤다(대우건설·휴마시스·대웅·코오롱). order_contracts의 검증된 `_contract_name`/`_counterparty`를
**fallback으로 재사용**(체결계약명/계약상대가 비면 발동 → 기존 동작 100% 보존). 순환
import(order_contracts→corporate_deals._extract_text 기존) 회피 위해 함수 내 지역 import.
→ **관점이 달라 tool은 둘이어도 파서의 견고함은 공유**해야 한다(한쪽 audit 성과를 다른 쪽이 상속).

## Takeaway

- **같은 공시도 관점이 다르면 다른 tool.** 단일공급계약 = corporate_deals(일감몰아주기, 부정)
  vs order_contracts(수주, 긍정). 강제로 한 tool에 두 프레임을 섞지 말 것.
- **공백 한 칸이 핵심 지표를 통째로 죽인다.** `매출액 대비`의 공백 때문에 적자기업 시그널이
  전부 None이었다. 라벨 매칭은 `\s*` 허용 + 변형 라벨 세트로.
- **정정 dedup은 본문 자체로 풀린다** — 정정본이 정정전/후를 담으므로 원본 rcept_no 참조 없이
  diff 추출 + 정정전 금액으로 원본 매칭. 키가 약한 도메인(조선업 익명 상대방)은 금액 체인으로 분리.
- **점수 미반영 fact는 구조로 보장하라.** order_signal을 compute_performance에 안 넣어
  classification이 수주에 영향받을 수 없게 — '점수 미반영'을 코드 경로로 강제.
- **정정본은 2부 구조(테이블 + 재공시 본문)** — 현재 유효값은 테이블 정정전이 아니라 재공시
  본문에서 파싱. 단위 정합 불변식(금액÷매출×100≈매출대비%)이 이 섞임을 대규모로 잡는다.
- **audit은 콜 누적을 배치마다 찍어라.** rate(분당/910)를 실시간 보면 페이싱 안전을 확인하며
  샘플을 키울 수 있다 (450사 분당 48로 한도 5% 사용).
