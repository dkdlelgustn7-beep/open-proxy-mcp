# 수주 tool 신설 (order_contracts)

## Context

적자 디폴트인 코스닥 바이오/기술주는 재무지표(ROE 등)만으론 안 보이는 축이 있다 —
**수주 = 미래 매출 가시성**. 단일판매·공급계약 공시(일반/자율공시/자회사)가 그 시그널인데,
corporate_deals가 같은 공시를 '일감몰아주기' 관점으로만 다뤄 수주 긍정 시그널이 약했다.

## 현황 진단 (구현 전)

- 검출은 됐다 — corporate_deals가 I001에서 일반+자율공시를 다 잡음(자율공시도 I001, 시장 실측).
- 그러나 (1) 기본 모드는 메타만(`include_details=False`) (2) **본문 파싱이 공백 변형에 깨짐** —
  `매출액 대비(%)`의 공백 한 칸 때문에 매출대비%가 전부 None, 코스닥은 금액조차 None.
  적자기업에 가장 중요한 '매출 대비 큰 수주'가 비어 있었다.

## Did

별도 tool `order_contracts` 신설 (16→17). corporate_deals와 같은 공시, 반대 관점(수주=긍정).

- **파싱 견고화** — 계약명 라벨 3종(`체결계약명`/`세부내용`(자율공시)/`판매ㆍ공급계약 내용`),
  금액 단위((원)/(천원)/(백만원)) 환산, `매출액\s*대비` 공백허용. 코스닥·조선·로봇·바이오 전수 통과.
- **기재정정 dedup + diff** (핵심) — 수주는 변경계약이 흔하다. 정정본 본문에 정정전/정정후가
  같이 있어 증액/감액을 직접 추출. dedup은 **multi-signal**: (계약명+상대방) 그룹 + 정정본의
  *정정전 금액* = 이전 건 금액이면 같은 계약 체인(최신본 유효). 금액 체인 불일치면 별개.
- **수주 시그널 요약** — 외부(계열 제외) 건수·총액·매출대비 최대/합계·정정 건수.
- **proxy_advise 매트릭스 fact** — 사내이사 성과(ROE/부채/CSR) 옆에 수주를 **별도 fact**로
  (점수 미반영 — compute_performance가 order를 안 받아 구조적 보장). 적자 코스닥에서
  수주 부재를 성과 저조로 오판하지 않게.

## 전수조사가 잡은 것 (multi-signal 검증)

사용자 지시로 전수조사하며 구현 — 두 버그를 실측이 잡음:
- 🔴 **한화 MCS Plant 정정 diff**: 표가 `계약금액(원) 매출대비(%) | 전값 | 후값` 구조라 정규식이
  라벨 뒤 숫자(294조·4)를 전/후로 오인 → 실제 **2940억→4245억(+44.4%)**. 큰금액 2개·소수 2개를
  순서로 뽑게 수정 (표양식 2종: 레인보우 '라벨 뒤 값' vs 한화 '라벨 앞 몰림').
- 🔴 **HD현대 자율공시 계약명 '?'**: 자율공시는 `체결계약명`이 아니라 `세부내용`(VLGC 2척) 라벨.
- 코스닥 검증: 에스티팜(올리고 898억·매출대비32.8%), 바이넥스(CDMO), 파마리서치(REJURAN® 31.3%).

## 시장 전수 audit (450사) — 단위 불변식이 정정본 버그 2개를 연쇄로 잡음

baseline 450사 전수 (총 482 DART콜·9분·분당 48 — 콜 누적을 배치마다 출력하는 재사용
audit 패턴). 수주 보유 167사, 유효계약 1060, **정정 603**(계약의 57% — 수주=변경계약 흔함 실증).

핵심 검증 = **단위 정합 불변식: 계약금액 ÷ 최근매출 × 100 ≈ 매출액대비%**. 이게 정정본
파싱 버그를 2라운드에 걸쳐 잡았다:

- **1차 (unit_mismatch 48)**: `_correction_diff`가 정정블록의 계약금액·최근매출을 [정정전/후]로
  오인 → `amount_after`가 최근매출값이 되어 contract_amount를 오염 (포스코 EV양극재 실제
  1.8조인데 4.7조). → 정정블록 `계약금액(원) [전] [후]` **라벨 직접 매칭** (포스코 '라벨 뒤 값'
  양식 우선, 한화 '라벨 몰림'은 최근매출 라벨 이전 구간 fallback).
- **2차 (unit_mismatch 74)**: 1차 수정 후 새 패턴 — `금액=정정후` / `매출대비=정정전`이 섞임
  (한화 MCS 5.7% vs 공시 294%). 근본 원인: **정정본은 `[정정전/후 테이블] + [정정후 반영
  재공시 본문]` 2부 구조**인데, 파서가 테이블의 정정전 값을 먼저 잡았다. → 정정본은 재공시
  본문(정정후)에서 금액·매출대비·계약명을 파싱하도록 수정. diff는 테이블에서 별도 추출.
- **최종: unit_mismatch 5 (0.5%)** — 남은 건 개별 양식 엣지(앱클론 매출대비 396% 같은 소형
  바이오 대형수주는 정상, 스피어 1건 단위 의심). flag 4사.

추가 발견: **계약금액이 달러 기준**인 공시(포스코 USD 10.7억×환율) — 본문에 원화 환산값이
같이 있어 그걸 사용. 통화도 '단위'의 한 축.

## Takeaway

- **같은 공시도 관점이 다르면 다른 tool.** 단일공급계약 = corporate_deals(일감몰아주기, 부정)
  vs order_contracts(수주, 긍정). 강제로 한 tool에 두 프레임을 섞지 말 것.
- **공백 한 칸이 핵심 지표를 통째로 죽인다.** `매출액 대비`의 공백 때문에 적자기업 시그널이
  전부 None이었다. 라벨 매칭은 `\s*` 허용 + 변형 라벨 세트로.
- **정정 dedup은 본문 자체로 풀린다** — 정정본이 정정전/후를 담으므로 원본 rcept_no 참조 없이
  diff 추출 + 정정전 금액으로 원본 매칭. 키가 약한 도메인(조선업 익명 상대방)은 금액 체인으로 분리.
- **점수 미반영 fact는 구조로 보장하라.** order_signal을 compute_performance에 안 넣어
  classification이 수주에 영향받을 수 없게 — '점수 미반영'을 코드 경로로 강제.
- **정정본은 2부 구조(테이블 + 재공시 본문)** — 현재 유효값은 테이블 정정전이 아니라 재공시
  본문에서 파싱. 단위 정합 불변식(금액÷매출×100≈매출대비%)이 이 섞임을 대규모로 잡는다.
- **audit은 콜 누적을 배치마다 찍어라.** rate(분당/910)를 실시간 보면 페이싱 안전을 확인하며
  샘플을 키울 수 있다 (450사 분당 48로 한도 5% 사용).
